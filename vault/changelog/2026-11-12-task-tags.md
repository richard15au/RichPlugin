## What changed
- Every task now carries a `tags: string[]` list, and new tasks start with an empty list.
- New `TaskList.addTag(id, tag)` trims the tag and adds it, ignoring a duplicate and returning the task; it throws `Task <id> not found` or `Tag cannot be empty`.
- New `TaskList.removeTag(id, tag)` trims the input and removes the tag, doing nothing if the tag is absent and throwing `Task <id> not found` for an unknown id.
- New `TaskList.byTag(tag)` returns a copy of the matching tasks in their original order, leaving `list()` untouched.
- `formatTask` now appends each tag as `#tag` after the title, for example `[ ] (medium) Write tests #docs #urgent`, and is unchanged when a task has no tags.

## Why
This implements [[task-tags]], which asked for short tags on each task, add and remove operations, filtering by tag and tags in the formatted output. Out of scope, as the spec says, were tag colours, renaming tags across tasks, prefix search, persistence and a UI. Tests in `src/tasks.test.ts` and `src/format.test.ts` were added or updated to cover trimming, duplicate and no-op removal, both errors, the ordering of `byTag` and the new format output.
